# MOV 预览修复（0.7.36）

日期：2026-10-23（America/Denver）。仅修复 MOV 兼容预览与视频卡片悬停/移动交互。

## 根因与修复

用户提供的 10.1.mov 是 PNG/RGBA 编码、2393×880、24fps、约 2.46 秒的透明特效素材。旧界面直接交给 Chromium 视频标签，解码失败后只显示“此格式需系统播放器”，不会自动调用已有 FFmpeg 转换。

现在 MOV 直接解码失败时进入串行兼容预览队列，生成 VP9 WebM 并保留透明像素。普通视频的 H.264 兼容输出明确采用 yuv420p。预览存在当前库，原 MOV 不变。

卡片悬停约 120ms 后播放；左右移动时按水平位置定位，停止移动约 180ms 后继续播放；离开或卡片移出 DOM 时停止并释放播放器。已生成缓存重开复用。

## 实测与边界

- 原版失败通过用户样本副本复现，源码与本机安装 0.7.36 验证自动预览、悬停、定位、停止移动后播放、移开停止、详情播放。
- 源码和安装版均验证：原素材副本离线、完整重开、缓存文件 mtime 不变、预览继续播放。
- 浏览器实际视频帧采样：335,361 个完全透明像素，156,943 个可见像素；源帧本身是半透明，不能以“必须有 alpha=255”作为通过条件。
- 首轮透明测试错误地要求 alpha>200；原文件该帧 alpha 最大仅 121。更正验收为透明区与可见区同时存在，未因此更改产品编码。
- MP4 的真实播放、空格暂停和逐帧快捷键回归通过；原用户 MOV SHA256 前后相同。NSIS 升级通过，安装 ASAR 与源码匹配。
- 未覆盖全部 MOV 编码、超长视频或所有色彩管理；首次转换需等待。原 MOV 保留，预览是缩放后的浏览代理，不代替剪辑素材。

## Aetodo 观察依据

本机 Aetodo 带有 resources/bin/ffmpeg.exe，package.json 包含 fluent-ffmpeg。REA 对 ASAR 报 Malformed ASAR；备用定向读取可读包清单，但未取得可验证的完整播放器链路。因此仅确认它具备额外解码工具，不宣称已证实它一定用同一转换格式、同一缓存或同一播放引擎。

## 可复用经验候选（待确认）

行动：以真实容器内编码和浏览器解码结果为依据，生成可复用透明预览。结果：该 PNG/RGBA MOV 可悬停播放并横向定位。原因：MOV 后缀不能代表浏览器支持其内部编码。验收：实际播放帧、透明区域、重启缓存和原素材哈希。反例：只改 MIME 或看到生成文件就算播放通过。边界：单个样本验证不能外推所有 MOV、HDR 和透明格式。
