# 一幕 AI 应用调研：从找素材到形成候选组

日期：2026-11-06（America/Denver）。状态：用户已认可四步方向，并要求先看界面；具体设计与产品接入尚未确认。
历史原型仅在开发工作区保存。后续已接入正式产品的功能和边界见[找素材验收](CANVAS-DISCOVERY-20261106.md)。
依据：同类产品官方资料、一幕现有调用链与 HANDOFF；未安装或实测竞品，不评价实际准确率、速度或中文效果。

## 推荐先解决的业务问题

创作者有很多素材，但只记得画面、用途或大概项目，不知道文件名，也不确定哪些能用。
建议先验证：**描述本次用途 → 连续缩小范围 → 预览与比较 → 把选中的素材加入画布候选组。**
交付物是可继续制作的素材选择结果。顶部接入多少模型，不是这个流程的验收指标。

上一轮建议的“生成描述与标签”可以成为检索的准备工作；本轮建议把“找到并选出可用素材”作为用户入口。两者不是已经确认的开发计划。

## 同类工具已经怎样做

| 产品 | 官方资料中的做法 | 一幕可以借鉴什么 | 边界 |
|---|---|---|---|
| [Eagle AI Search](https://en.eagle.cool/blog/post/eagle-plugin-ai-search) | 参考图检索视觉相似项；自然语言匹配名称、描述、备注等文字资料；本地运行 | 先找一个接近的，再以它为参考继续找；保留原有筛选 | 该文明确说自然语言搜索依赖文字资料，不能据此宣称可直接理解无描述图片 |
| [Premiere Media Intelligence](https://helpx.adobe.com/premiere/desktop/organize-media/file-organization/media-intelligence-and-search-panel.html) | 按画面描述找到视频中的片段，结果带入点/出点，可进入剪辑序列 | 搜索应返回可用时段，而不只返回几十分钟的文件 | 需要先分析素材；官方说明视觉搜索不做 OCR，人物外观搜索不等于身份识别 |
| [Jumper](https://getjumper.io/ai-agents) | 本地分析，向 Codex/Claude 等开放画面、对白、人物搜索以及选段、导出等操作 | 自然语言负责组织多个工具，结果进入实际剪辑流程；外部助手和软件共用能力 | 产品能力与宿主支持需实测；商业软件的 API 可用不等于允许复制实现或免费使用 |
| [Adobe AEM Content Discovery](https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/ai-in-aem/agentic-capabilities/content-advisor/discovery/use-cases) | 通过对话组合目录、格式、日期、状态等条件；对已有结果继续筛选、分组、排序、比较 | 多轮对话记住结果范围；把“再缩小一点”变成真实筛选 | 这是企业云素材管理产品，借鉴交互即可，不照搬其云平台与组织管理 |

这些是官方功能说明，不是本轮独立效果验证。Premiere 的[搜索使用说明](https://helpx.adobe.com/premiere/desktop/organize-media/file-organization/search-for-media-using-ai-powered-media-intelligence.html)仍标注视觉查询仅支持英语，不能直接承诺中文任务体验相同。

## 1. 能不能靠对话找到素材范围

可以，且范围筛选可以先复用现有资料。真正的多轮对话需要保留搜索条件与候选集合，而非每句话重新从全库找。

以下是一幕的建议交互，不是已经实现的演示：

> 用户：为产品短片找些有生活感的室内画面，横屏，先看这个项目。
>
> 软件：展示候选卡片；条件栏显示“当前项目、横屏、室内”，并标明生活感是内容排序依据。
>
> 用户：第二张方向对，找更接近它的；人物少一点。
>
> 软件：保留项目与横屏限制，以第二张为参考重排候选；允许撤销这轮调整。
>
> 用户：把我勾选的几张放进画布的“开场候选”。
>
> 软件：建立素材引用组，定位到画布；原文件保持原位置。

目录、尺寸、格式、日期、本人确认状态应按真实字段筛选。风格、情绪与用途属于排序建议，不能伪装成准确属性。
只在答案会显著改变范围时追问；其余条件直接显示在可编辑的筛选栏中。

## 2. 除了打字，还有哪些找法

| 用户当时的困境 | 合适的入口 | 需要的能力 |
|---|---|---|
| 说不清风格，但知道哪张接近 | 拖入参考图，或点“找相似” | 图片/视频帧相似检索；可继续用文字修正 |
| 第一批不太对，但能指出哪里不对 | 点“更像这张”，排除不合适的结果 | 保存本轮偏好并调整排序，不必先训练个人模型 |
| 记得一句话，却不知道出现在哪里 | 搜对白或画面上的文字 | 带时间码的语音转写、OCR；两者与普通视觉搜索不同 |
| 不知道这个库里有什么 | 先看素材概览，再进入某一类 | 按已有目录/标签/类型统计；内容主题概览需要另做分析 |
| 有脚本，想知道哪些镜头可以复用 | 按脚本段落查看候选与缺口 | 将需求拆成检索任务，逐段提供可追溯候选；宜后续再验证 |

一个值得后续研究的设计是 Jumper 的[分层素材摘要](https://getjumper.io/blog/AI_summaries_of_video_footage)：从场景描述逐级汇总，保留源时间范围，先了解有什么，再定向搜索。
这适合“我不知道库里有什么”的问题，但不应在第一版就全库生成大批摘要。先判断现有目录、标签和缩略图是否已足够缩小范围。

## 3. 对话框里应该放什么

建议把入口命名为“找素材”，从素材库或画布打开，默认继承当前项目与选择范围。模型配置放在设置里。

- 对话旁显示真实素材卡片，能直接预览；视频检索成熟后显示命中时间段。
- 顶部显示本轮范围、过滤条件和已分析范围，允许点击修改、回退上一轮。
- 每项提供“找相似、加入候选、定位原文件”；多选后提供“加入画布组”。
- 给出命中依据，例如已有标签、备注原文或实际匹配帧；“适合开场”明确标为建议。

不要求所有动作都输入一句话：精确筛选继续用按钮，模糊需求用自然语言，最后由用户通过预览选择。
“未分析到这些素材”和“分析后没有合适结果”必须分开显示。缺失原件也不应被包装成可直接使用的结果。

## 复用什么，补什么

一幕已有元数据检索、本地 Chinese-CLIP 图片/封面索引、素材预览、画布分组和 MCP 接口，可作为基础。
当前 MCP 的 `yimu_search` 只查名称/标签/备注；尚未向助手统一开放本地语义检索和画布候选组操作，不能把上面的交互当成现成功能。

建议把搜索、筛选、选择与入组做成同一组可调用操作，让外部 Codex 和未来内置对话共用。
大模型负责理解需求、保留条件和组织调用；尺寸/格式筛选交给现有数据库，画面匹配交给现有或成熟检索模型。
普通找素材不必每次把全库图片重新发送给云端；只分析新增/变化素材，并复用分析结果。

若后续确需整段视频理解，可先评估成熟工具的正式 API、MCP 与授权条件。此次没有验证 Jumper 与一幕的直接互通，也没有决定采购或新增依赖。
云端看图需要支持图像输入的模型；现有文字试用链路不能自动获得这项能力。

## 只验证一个假设

假设：**在同一个真实项目中，连续对话和参考图修正能更快形成可用候选组。**

建议先选一个小素材集合与 10 条真实找素材任务，对比原来的目录/关键词搜索和候选流程。
记录首次找到可用素材的时间、前 10 项实际可用数量、纠正次数、最终入组是否省步骤。
首轮只做图片与已生成封面的候选检索；视频时段、OCR、转写、脚本配素材不同时扩张。

如果只让回复更漂亮，却没有更快找到和选出素材，应先修检索与结果操作。本人觉得顺手之后，再观察他人能否用自己的素材复做；本轮调研不能证明市场需求或付费意愿。

## 经验候选，待确认与实测

- 行动：对照官方文档，把竞品 AI 入口拆成检索、继续筛选、预览和结果操作。
- 结果：形成“描述用途到画布候选组”的单一候选流程；没有完成软件或用户验证。
- 原因：素材工作的收益可以落在找到、选出和使用文件的步骤上，便于验收。
- 验收：用真实找素材任务比较耗时、可用候选、纠正次数和入组操作；尚未执行。
- 反例：只有通用聊天回复或自动标签数量增长，用户依然需要逐个翻文件。
- 边界：竞品资料不等于实机表现；不外推中文准确率、大库性能、市场需求或收益。
