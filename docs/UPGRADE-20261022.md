# 本机升级修复与验证

## 结论

同一份 0.7.31 安装包通过正式 NSIS 流程完成升级与再次安装，返回码均为 0；系统注册版本现为 0.7.31，新卸载器已部署。未修改产品源码或安装包字节，不需要为安装环境问题再升产品版本。

## 原因与证据边界

- 空 NSIS 程序从 K 盘运行、使用默认 C 盘 TEMP 时，弹出 `Error writing temporary file. Make sure your temp folder is valid.`，返回 2；尚未进入安装业务。
- 空程序改用工作区 TEMP 可启动；同一字节的 EXE 复制到 LOCALAPPDATA 后，用默认 TEMP 也可启动。这是本机执行位置/临时文件访问环境差异，不是旧卸载器已损坏的证据。
- 原先切换构建 TEMP 后直接尝试安装，混入了不同的运行条件。跨卷 MoveFileEx(flags=0) 探针返回 17，但这不能证明历史卸载失败就是跨卷搬移；不把该假设当根因。
- REA 进程捕获不支持 Windows，原生窗口观测仅支持 macOS；本轮改用 Win32 窗口文本、最小 NSIS 程序和真实安装回执。底层访问限制来自哪个系统组件尚未确定。
- NSIS 上游启动代码在加载安装脚本前检查临时文件；失败可返回 2：[Main.c](https://github.com/kichik/nsis/blob/master/Source/exehead/Main.c)。本机结论以实际最小实验为准。

## 修复

- 新增 `scripts/install-local.ps1`：校验安装位置，将安装包复制到用户本机缓存并核对 SHA-256，使用进程内的默认 TEMP/TMP 执行正式安装。
- 保留 NSIS 的旧版本卸载、进程关闭、安装注册和数据保护；不改系统 TEMP、ACL 或注册表以跳过卸载，不再手工覆盖程序目录。
- 根目录 `安装或升级一幕.cmd` 提供双击入口，成功后打开软件。当前辅助脚本只支持本机默认的按用户安装目录；检测到其他目录会停止并说明。
- 安装失败不会自动手工覆盖；每次生成独立 `evidence/upgrade-日期-时间/install.json`。本机缓存保留安装包，可追溯，不纳入应用分发内容。

## 经验候选（待确认）

行动：先用同字节空安装器比较执行位置和 TEMP，再处理产品安装。结果：正常本机暂存启动使正式升级与再次安装通过。原因：返回码 2 可出现在安装逻辑之前。验收：空程序对照、正式安装退出码、注册版本、程序哈希和偏好文件哈希。反例：只据退出码判定旧卸载器坏了，或继续手工覆盖掩盖注册版本。边界：仅本机验证，底层安全组件未归因。
