## 2. 推荐的归类方案

### 先整理一幕入口，保留原包

| 当前入口 | 建议显示名 | 下一层优先按什么找 |
|---|---|---|
| AE预设 | 01_AE模板与预设 | 文字标题、MG与卡通、科技HUD、转场、背景、内置效果 |
| PR预设 | 02_PR模板与预设 | 字幕标题、标注图形、转场、循环背景、数据动画 |
| 视频素材 | 03_视频与包装元素 | 光效、烟雾火焰、遮罩纹理、背景、MG元素、实拍参考 |
| Sound | 04_音乐与配乐 | 情绪、用途为标签；原有 Music / 影视配乐包先保留 |
| SFX | 05_音效与环境声 | 转场、冲击、界面科技、机械、自然、人物动物、卡通魔法 |

这些名称和二级分组是建议，尚未执行。不要一次拆开几万个文件，也不要把 AE 包中的配套声音或视频单独搬走。
“国外”与品牌包不应成为最终用途类别；先保留它们作为来源目录，用标签补充用途，无法判断的标“待复核”。
以后确有对应素材再增加“图片与设计”“字体”“待整理”等入口，不先造大量空目录。

连接库已有显示名和虚拟父级能力，见 src/folder-tree.cjs。显示归组可以不改磁盘路径；托管区重命名可能实际改盘，不能混用。
新建任意虚拟容器、智能集合、整理预览等不应当作现成功能承诺；实施前须检查入口和约束。

### 用标签跨目录找，避免再复制一份

| 标签维度 | 示例 | 可靠来源 |
|---|---|---|
| 工具 / 格式 | AE、PR、MOGRT、FFX | 扩展名和已知工具规则 |
| 用途 | 文字标题、HUD、转场、环境声 | 清楚的目录和文件名；含糊者待复核 |
| 画面内容 | 人物、城市、海洋 | 图片或有效封面；AI 只作候选 |
| 风格 / 声音情绪 | 卡通、复古、轻快、紧张 | 有依据的原标签、人工试听；不能由封面推断音乐 |
| 来源 / 授权 | 原包名称、来源网址、待核实 | 原包说明或本人确认；目录名不能证明商用许可 |

例如 Whoosh 可建议“转场”，Impact 可建议“冲击”；先抽听确认词义和误判，再扩大映射。
不把来源包中的声音直接等同于整个包的画面风格，不自动将所有音频加“轻快”等主观标签。

### 分三步实施

1. 先导出“原路径 → 建议显示分组 → 建议标签 → 依据”的预览清单，保留索引备份，不改原文件。
2. 先处理一个常用子包，建议 100–200 条；确认显示、搜索、配套文件和重开后结果，再批量应用同一规则。
3. 最后对有实际画面价值的图片、视频封面和模板效果图做 AI 索引；声音先用目录与名称，不跑封面识声。

验收限三项：①原路径与工程配套关系不变；②标签/分组重开保留且能检索；③典型检索结果经预览或试听核实。
分类迁移、删除、去重和真实磁盘搬家不包含在本轮方案执行中。后续如需实际迁移，先单独验证依赖与回退。

## 3. 右键“语义索引”与“自动打标签”怎么用

| 当前入口 / 操作 | 实际作用 | 不会自动发生的事 |
|---|---|---|
| 右键 → AI 创建语义化索引 | 为所选素材的图片或封面存画面向量 | 不追加可见标签 |
| 本地 AI 窗口 → 建立语义索引 | 扫描全库符合画面条件的素材 | 不只处理当前文件夹或选中项 |
| 顶部搜索 → AI 语义 | 用描述在已成功索引的素材中按相关度排序 | 不理解整段视频、声音或工程图层 |
| 右键 → AI 自动打标签 | 打开设置窗口；还需点“为所选素材追加标签” | 右键点完并不立即加标签 |
| 窗口里的候选词列表 | 限定模型可以选择的词，每条最多追加 3 个 | 不是已生成的标签，也不是任意内容自动写描述 |

**画面搜索的现有用法**：先选少量图片/有效效果封面 → 右键建立索引 → 顶部切到“AI 语义” → 输入符合素材库的描述，如“科技界面” → 预览核对结果。

**打标签的现有用法**：先选素材 → 右键“AI 自动打标签” → 按这批素材调整候选词 → 点“为所选素材追加标签” → 在资料栏查看并修改。
它保留原标签；相似度不达门槛时可以不加，最多 3 个不是保证加 3 个。索引和打标签可以独立使用，打标签不要求先建立全库索引。

图片按可用封面优先、否则原图；视频/工程按封面分析。动画预览不等于分析完整动画。音乐封面只能描述画面，不能识别旋律、情绪或音效类别。
若“检测素材”指 AE 工程检查或扫描文件信息，它们与 AI 打标签是独立功能。

## 3.1 整文件夹打标与“自己定义语义”

可以按文件夹批量处理，实际应逐条分析文件，再将结果汇总到文件夹；不能将一张封面或文件夹名当成所有文件的内容结论。
现有基础是批量处理所选素材；进入文件夹、确认筛选与包含子目录设置、在素材区 Ctrl+A，可选择当前筛选范围全部结果，而非只有已加载页。
独立的文件夹右键“分析并打标”、范围预览和文件夹内容摘要尚未实现，不能当成现成功能。

建议入口：右键文件夹 → 选择是否包含子文件夹 → 查看支持/跳过数量 → 小批分析 → 预览建议 → 确认写入；支持保留原标签、取消和重做。
语义索引无需先打标签：模型将画面转换成数字向量，搜索时比较描述与画面的接近程度。
当前打标则只在预先提供的候选词中挑选，最多 3 个，不会自由生成新词或文件夹摘要；“开放生成标签”需另加模型与结果确认流程。
音频需要依据名称/路径的规则或新增声音模型，现有画面模型不能理解音乐和音效；是否采用本地/联网服务、费用与性能均未决定。

## 3.3 约 191 MB 的模型与 API Key 的区别

当前内置模型为 Xenova/chinese-clip-vit-base-patch16，固定修订 f26904860903e70e050b8f48255e5f48401816e9、q8 量化版。
程序通过 Transformers.js 从 Hugging Face 配置的下载源取得；[模型作者页面](https://huggingface.co/Xenova/chinese-clip-vit-base-patch16)说明它是 Chinese-CLIP 的 ONNX 版本，用于图文匹配/候选类别匹配。
本机主文件 model_quantized.onnx 实测 190,842,404 字节，约 191 MB，另有少量配置和分词文件。该体积是模型权重，不是素材数量或素材索引大小。

普通应用路径下已找到完整文件：
`C:\Users\Administrator\AppData\Roaming\YimuCraft\models\Xenova\chinese-clip-vit-base-patch16\f26904860903e70e050b8f48255e5f48401816e9\onnx\model_quantized.onnx`。
Codex LocalCache 下也观察到同名文件；本次确认文件存在与大小，未用网络抓包还原历史下载请求。

它为画面语义索引、文字找画面、以图搜图和候选词打标提供计算能力；不能当作聊天、生图或识声模型。
下载需要联网，后续这条本地识别流程使用本地文件，不需要 API Key，也没有每次调用服务商的费用；消耗本机 CPU/内存。

API Key 是调用服务的访问凭证，并不是另一个下载到本机的模型。远程服务通常在服务商服务器上计算，功能、费用和是否支持图片取决于具体接口。
当前一幕 API 设置实际用于服务商配置、模型列表与文字试用；试用只发送输入文字，不附带素材。也支持本机兼容 API，因此“API”不必然等于云端。
本地 AI 与该设置为独立调用链：填写 Key 或选择当前服务商，不会自动把语义索引切到远程模型，也不会自动开启全库上传分析。

### Chinese-CLIP 不是预先打好标签的素材库

191 MB 主文件是训练后神经网络的权重，不是按分类存放的标签表或已标注图片集合。
它的图像编码器读取新图片、文字编码器读取文本，分别生成数字向量并比较接近程度；这是实际视觉识别/跨模态匹配能力。
建立索引是为各素材计算特征，不是在为素材库重新训练模型，也不必先给每条生成关键词。
模型能匹配画面和用户临时输入的描述；一幕打标签功能所用的默认候选词位于程序 DEFAULT_LABELS，是应用的选择，不能等同于模型全部能力。
它不直接生成长篇画面描述、自由标签或复杂推理；细粒度文字、动作和多帧理解的效果不能据此保证。
原理依据：[原作者模型卡](https://huggingface.co/OFA-Sys/chinese-clip-vit-base-patch16)的图像/文字编码与相似度示例。

这些资料只证明可选接口具备相应输入/任务，不证明本机已配置、账号有权限或一幕已接入；不默认新开服务或购买套餐。

### 当前配置的现实限制

只读取并输出了服务商名称、模型 ID 和协议，未显示/发送任何 Key。当前默认模型为 DeepSeek deepseek-v4-pro，另有 Kimi kimi-k3、MiniMax MiniMax-M3 配置；verifiedAt 均为 0，不能将保存配置当作真实调用已通过。
DeepSeek 官方 [Anthropic 兼容说明](https://api-docs.deepseek.com/guides/anthropic_api/)明确 deepseek-v4-pro 不处理图片，图片会替换为 Unsupported Image；[视觉接口](https://api-docs.deepseek.com/guides/vision/)说明 deepseek-flash 支持图片。
因此不得用当前默认模型静默吞掉图片，再把基于文件名的猜测称为看图结果。其他已配模型的图像/声音能力需按准确模型与接口验证，不能只根据品牌或接口兼容性推定。
MiniMax 公开资料虽有图片/音频输入结构及 M3 图片/视频说明，本轮不足以确认当前 MiniMax-M3 配置支持实际音频理解；Kimi 当前精确模型能力本轮无法确认。

### 推荐产品流程与数据结构

入口为“右键文件夹 → AI 分析与打标”；先显示本文件夹/含子文件夹、文件类型、图片/音频对应服务商和模型、将发送的内容与预计任务量。
默认先跑一个小样本供预览，确认效果和消耗后运行所选范围；可选择自动追加标签，保留任务记录和撤销，不覆盖用户已有标签/备注。
后台逐条处理、可取消/续跑、按文件指纹和模型/提示版本复用已有分析；限制并发，保留逐项失败原因与真实用量，不将未完成计为成功。
接口不兼容应明确跳过并说明原因；不能静默退回文件名猜测或音频封面打标。模型输出只当结构化数据校验，不执行其中指令。

建议新增独立的 AI 分析记录：素材 ID、输入指纹、模型/服务商、分析范围/时间戳、描述、候选标签、依据、原始响应摘要及任务来源。
AI 描述不能塞进并覆盖用户的备注。标签应用时区分本次新增和既有内容，便于撤销与重分析；原媒体仍保持原样。
“生成语义说明”与“建立语义搜索向量”不同：聊天结果不会自动变成可比较向量。须把说明/标签接入查询，并为描述与音频结果另配文本语义索引。
不得将不同模型、不同维度的向量直接混在同一索引比较。保留现有 CLIP 本地视觉检索，云端分析按需补内容说明；两者不是只能二选一。

### 开发与验收范围

需扩展模型服务的多模态请求、媒体抽样、后台任务、结果校验/持久化、文件夹 UI 和检索；不是将试用文字换成文件路径就能完成。
验收三项：①自有/隔离样本分别真实看图、看多帧、听声音并人工核对标签；②取消/重开能续跑，重复执行不重复加标签且费用/范围可见；③标签/描述与检索结果重开保留，原件摘要不变，失败/不支持不冒充成功。
本轮完成能力核查和具体方案，尚未改代码、发送媒体、调用付费 API、批量分析或安装新版本。

首次运行自动弹出；完成或跳过后正常启动不反复弹出。从“帮助 → 新手引导”可随时重开。
引导状态保存在应用设置中，与素材/标签分开；后续升级是否新增专项引导应另判，不默认每次升级打扰用户。

|---|---|---|

引导不能自动替用户导入整盘、下载模型或执行全库任务；进入有关操作时必须让用户看清范围并自行触发。
没有素材或不想操作时可下一步/跳过，不通过虚构数据或假结果冒充真实操作；目标在菜单/弹窗中时须正确定位并支持退出。
AI 作为可选分支，普通素材管理不被下载模型或六万条任务卡住；首次主引导不塞入全部高级功能。

### 把 AI 窗口拆成三个明确任务

- **按画面搜索**：状态说明已索引多少可分析素材，入口明确“索引所选 / 当前文件夹 / 全库”。
- **用参考图找**：选择参考图后显示匹配范围，再预览结果。
- **生成标签**：显示选中数量，按图片、视频/模板提供候选词；先展示建议，再确认追加并支持撤销。

后两项中的预览确认、撤销、按类型候选词、范围选择和后台任务体验均是待开发建议，不能写成已有功能。
音频入口应明确“当前暂不支持识声标签”，并提供按名称/目录整理的现有路径。

引导的必要验收：①首次弹出、完成/跳过后不再弹出、帮助可重开；②五步正确定位真实控件、前后切换与退出正常；③首次引导不擅自导入、下载或启动全库 AI。
下一步优先级：实现五步主引导；文件夹分析的范围与类型过滤、CPU 占用控制单独按实际授权落地。当前仅修正方案，没有修改安装版。
