# AE 按需联动修复

用户确认：临时暂停 YimuCraft 每秒扫描后，AE 操作卡滞立即消失。本轮按用户要求修复源码和本机部署；后续验证已按用户明确指示停止。

## 行为变化
- 旧：Startup 脚本每秒遍历整个项目、读取字体/素材并写 ae-state.json，即使不用联动也继续。
- 新：Startup 只保留迁移兼容处理，不读工程、不写状态、不建立定时器。桌面刷新直接提交带唯一 ID 的一次性脚本，等待对应回执。
- 新：不再相信旧状态文件；请求使用独立 on-demand 子目录，避免旧 CEP/Startup 队列重复执行。启动器退出但没有回执时，阻止重复提交。
- 新：普通导入只返回工程路径、未保存状态和条目数，不顺带扫描原有图层。收集及用户明确要求的文件验证/预览保留必要依赖检查。
- 界面入口改为“刷新 AE 工程信息”。安装打包面板时一并替换旧扫描脚本，并备份旧文件。

- 停止验证前：核心 116/116、目录版 0.7.58 的菜单与隔离空库启动通过；未做新的模型调用或媒体渲染。

## 经验候选（待确认）
- 行动：取消宿主每秒全量轮询，改为用户操作触发并凭唯一回执确认。
- 结果：用户报告暂停旧轮询后恢复流畅；新代码通过自动化回归，宿主最终体验未验。
- 原因：统计平均 CPU 无法判断周期性宿主阻塞；状态读取不应要求宿主永久扫描。
- 验收：刷新/收集可用，闲置无扫描，重启不恢复旧循环，用户操作顺畅。
- 反例：仅把 1 秒改成 5 秒，仍然让未使用的联动遍历全工程。
- 边界：本机旧逻辑的对照成立；不外推所有 AE 卡顿，也不将源码测试当成宿主体验通过。
