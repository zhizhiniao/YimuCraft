## 结论

未变化文件重新导入覆盖预览关联、生成接口每次新建目录，均已用真实 MOV 复现并修复。
实际安装 EXE 退出并重开后，音频波形和 MOV 预览均复用；缓存内容/摘要/修改时间保持，新增解码/转换为 0。

## MOV 实际结果

- 原生不能播放的 PNG/RGBA MOV 自动生成 VP9 WebM，真实播放器开头、中间、结尾及跳播通过。
- 再次请求生成，返回同一个已完成产物，文件摘要、大小和 mtime 不变；不再每次调用都创建一份新视频。
- 未改变文件再次执行库导入，SQLite 仍指向 WebM。关闭程序，暂时移开隔离库内的原 MOV，再开安装 EXE，预览仍能播放。
- 重开新增视频转换 **0 次**；输出仍为同一路径、309,974 字节，同一 SHA-256 与 mtime。原 MOV 副本在 finally 恢复。
- Chromium 抽样 35,464 个 alpha 值，与独立 FFmpeg 9 解码源帧并缩放后的参考比较，平均绝对误差 **1.739/255**，低于事先设定的 5/255；透明/可见区均保留。
- 独立 FFmpeg 完整解码安装版生成的 WebM，退出码 0；原先用户 MOV 与 200 个真实库原音频再次读取校验均未变。

证据：`installed-mov-report.json`、`installed-mov-reopen-events.json`、`installed-alpha-reference.png`、`installed-chromium.pftrace`、`verification.json`。

## 改动与复用规则

| 文件 | 行为 |
| --- | --- |
| src/renderer.js、audio-card.js、virtual-pages.js | 可见波形队列、按需媒体源、复用已取得的波形/时长，卸载卡片撤销排队任务；MOV 提示改为准备预览，不预先断言正在转换 |
| src/library.cjs | 不变文件重导入保留仍存在的预览；源改变后清除与旧生成视频同目录的自动封面关联 |
| src/video-preview-cache.cjs、media-preview.cjs | 源版本参考记录定位内容摘要＋转换规则对应的完成产物；新/疑似变化源才计算摘要，热打开不全量哈希原媒体；同键请求合并 |
| src/main.cjs、media-preview.cjs | 保持原 IPC 来源与素材检查，区分读取与生成状态，退出时终止转换子进程 |

先写完整产物和清单，再发布目录；源记录与库关联可后补。完成结果可以在索引关联缺失时按内容键发现。
原有有效旧预览继续使用，不全库重新生成。修复前已丢失关联且没有身份记录的旧预览，可能仍需首次补生成一次。
无按时间到期；素材内容/转换规则变化、缓存缺失或损坏时重建。项目画布原有 200 项/2 GiB 淘汰策略未调整，未观察到它是本次主要原因。
缓存源参考记录以大小/mtime/文件身份快速定位；重导入保留关联主要比较大小与 mtime。外部修改内容又保留大小和 mtime 的特例仍需内容复核，未宣称能无读盘发现所有变化。
